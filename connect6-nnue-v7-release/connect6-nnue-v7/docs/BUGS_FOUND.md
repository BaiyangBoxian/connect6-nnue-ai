# BUGS_FOUND.md — 7 个致命 bug

## 1. iterBest bug（根因级）
**现象**：多任务 net 0% 抓 fork。
**诊断**：`while(depth < maxDepth)` 迭代加深中 `iterBest = mv` **无条件赋值**——最后一层迭代的首节点被留下，即使它劣于浅层的 alpha 选择。
**修复**：`if (v > alpha) { alpha = v; iterBest = mv; }`（alpha 提升才更新）。

## 2. eval 非对称
**现象**：深度0 空局面黑=+2733，白不是 -2733。
**诊断**：`eval_side()` 里 `nnA`/`nnB`、`ourOpen4`/`oppOpen4` 两侧权重不同（+1188/-1188, +1820/-1638）。
**修复**：对称化，零和 ✅（黑=+622/白=-622）。

## 3. WDL 方向
**现象**：白方"必败局面"看成胜势。
**诊断**：`wdl` 标签是绝对胜方，头没做行棋方归一。
**修复**：`winner_mover=(winner==2)?0:1`，`wdl=(mover==winner_mover)?2:0`，loss 用 KL。

## 4. 规则错误（首手）
**现象**：旧数据全是"第一手 2 子"。
**诊断**：`gen_multitask.cpp` 每手 2 子不分手数。
**修复**：`plies==0` 只落 1 子；`b6_search` 空盘 `out[2]=-1`。旧数据作废（964M → `_invalid_rule/`）。

## 5. 特征编码不一致（防守漏洞根因）
**现象**：实战防守差，benchmark 防守反击题丢分。
**诊断**：gen(训练数据) 的 `f[12]/f[13]` 用 `to[]`(OPP 对手威胁)，引擎推理的 `f[12]/f[13]` 用 `ts[]`(SELF 自己) → **防守信号被调换**。
**修复**：引擎改用 `to[]`，与数据约定一致。benchmark 85 → 90，防守反击 19/20。

## 6. has6 颜色码错
**现象**：AI 自对弈 1 子就"判负"。
**诊断**：`has6(colour)` 用 0/1 侧旗 vs `b6_cell` 的 1/2 棋盘码 → 空盘误判"成六"。
**修复**：`has6(colour+1)`。

## 7. phase3 置换表删除 BUG / NN_H 宏错
**现象**：NNUE 722 改 736 后 0% 抓 fork；花屏（点一子四角摆四子）。
**诊断**：(a) 删除 phase3 置换表时 `search_phase3_table.cpp` 主体拷贝丢失、**分隔线**留着，被引擎当棋盘码；(b) `NN_H2` 宏是 `NN_H1/4`，改 736 时 `NN_H1=736` → `NN_H2=184` 而导出权重 `H2=64` 维不匹配。
**修复**：删错块；`NN_H1=256/NN_H2=64` 显式定义。
